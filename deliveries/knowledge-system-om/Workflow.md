# 知识蒸馏与视频生产工作流

本次在现有分散视频工程旁新增统一适配层；没有把旧工程假称为已有的无人值守平台。Open Montage通过真实Python注册表接入，而不是当成一个名为“Open Montage”的MCP工具调用。

```mermaid
flowchart LR
 A[PDF与素材入库：来源哈希、页码] --> B[知识蒸馏：区分原文观点与新增演绎]
 B --> C[内容检查：证据、情境边界、承诺表达]
 C --> D[AI导演：镜头含义与技术需求]
 D --> E[统一适配层：契约、可用性、错误、缓存]
 E --> F[Open Montage：素材探测、合成预检、渲染入口]
 F --> G[Remotion / 条件适用时的Blender等]
 G --> H[Open Montage：镜头拼接、混音]
 H --> I[FFmpeg：保留画面数据流的封装]
 I --> J[自动技术检查与实际画面审阅]
 J --> K[版本化交付与下载校验]
```

## 各阶段的输入、输出与复用

| 阶段 | 输入 | 执行者 | 输出与检查 |
|---|---|---|---|
| 原料接入 | 用户PDF、音频、视频 | PDF提取器；Open Montage `audio_probe` | 原文件哈希、页码文本、实际媒体信息；文件内指令只作为资料内容 |
| 知识蒸馏 | 分页原文 | 当前Codex进行语义判断 | `knowledge-distillation.json`：观点、页码证据、证据层级、采用/不采用理由 |
| 内容约束 | 原创屏幕文案 | AI审阅＋JSX AST提取＋词语检查 | 原文观点不冒充研究；新增案例标为演绎；排除效果承诺；程序词语检查不能代替事实核查 |
| 导演决策 | 已筛选知识与镜头目标 | 当前Codex＋`director.route_shots()` | 画面解释任务、镜头规格、技术需求与选择理由；不因工具存在而强行使用 |
| 工具审计 | 注册表、真实命令 | Open Montage注册表＋环境检查 | 声明能力与实测能力分开；未配置、未验证、不可用分别记录 |
| 资产与缓存 | 文件、源代码、字体、参数 | Open Montage `AssetCache` | 复用上游缓存；适配层补充输入内容哈希与输出SHA-256核对；单文件结果缓存，多文件抽帧暂不缓存 |
| 制作 | 镜头技术需求 | Open Montage `video_compose` 调用项目专属Remotion入口 | 帧驱动图形；无库存场景模板。三维需求可路由到已安装的Blender工具，但本次没有声称已测试三维成片 |
| 时间轴与剪辑 | 明确的镜头顺序与时间 | Open Montage `composition_validator`、`video_stitch`；补充整数帧校验 | 渲染前检查资产和时长；检查空隙/越界；一致规格镜头使用视频流拼接 |
| 声音 | 用户音乐、动作事件 | Open Montage裁切、`audio_mixer.full_mix`；本地节奏分析与SFX生成 | 10秒混音；起音/BPM候选与动作帧记录；不把算法候选称为已人工确认的重拍 |
| 最终封装 | 拼接画面、混音 | FFmpeg适配器 | 复制视频数据流，仅封装/编码音频；校验封装前后视频数据流一致 |
| 审核 | 实际MP4与原创文案 | Open Montage探测/抽帧＋全解码/全帧基础指标＋实际画面检查 | 不把上游音量推断的“有旁白”、默认的“文字可读”等字段作为语义事实；音轨技术检测与人耳试听分开 |
| 交付 | 视频、工程、报告 | 版本化打包与下载校验 | 文件大小、SHA-256、ZIP CRC；不覆盖旧作品或main |

## 统一调度契约

调用入口：`python -m orchestrator.cli`，当前使用Open Montage的隔离Python解释器运行。此CLI是本次新增的适配入口，不是上游已有命令。

每个任务声明：`id`、`capability`、`params`、`inputs`、`cache`、`allow_fallback`。所有工具返回统一包络：`success`、`status`、`error_code`、`data`、`attempts`、`artifact_hashes`。工具的原始结果和实际命令保留在项目的`artifacts/jobs`。

Open Montage工具直接复用其`input_schema`；本地工具有独立JSON Schema。上游部分输出schema为空，因此本层统一验证结果包络与交付媒体契约，不虚构上游具有完整输出类型检查。

任务按依赖顺序执行，上游失败则下游阻塞。默认不启用回退；只有显式允许且能力等价时才使用候选。已实测的回退是探测工具到原生ffprobe。Remotion备用入口仅支持声明的无外部props路径；不支持的参数被拒绝，不悄悄丢弃。三维任务没有二维替代候选。

## 缓存与局部修改

缓存沿用Open Montage的`lib.asset_cache.AssetCache`，不是另造一份媒体缓存系统。本层计算工具版本、仓库提交、适配实现、参数和声明输入文件内容的指纹，再检查恢复文件的SHA-256。重复渲染任务已实际恢复文件，第二次调用没有Remotion渲染命令。

当前粒度是“任务/镜头＋其声明输入”；共同源文件修改会使引用它的多个镜头失效。尚未实现组件AST级依赖裁剪、跨机器缓存或并发项目调度服务。后续新增能力需补充契约与实测记录，不能仅凭注册表中的available启用正式生产。

## 当前自动化边界

语义蒸馏、证据取舍和导演判断由当前Codex执行，形成结构化产物；调度层自动执行这些任务、处理依赖和错误、恢复缓存并记录证据。本次没有把任意PDF到高质量整片实现为无需审阅的无人值守服务，也没有调用新的付费生成API。
